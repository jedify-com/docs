This walks through building a dashboard the way it actually happens: **you describe it, your agent does the work.** Connect in [Builder mode](/mcp/modes) first, then talk to your agent in plain language.

The example: a **team training dashboard** — completion rates with a couple of charts, filterable by department and office, over a date range.

## 1. Describe what you want

**You say:**

```text
Build a training dashboard for our team. I want:
- a number showing overall completion rate
- a bar chart of completion by department
- filters for department and office, and a date range
Use the data in Jedify.
```

That's enough to start. You don't need to know function names, SQL, or the SDK — your agent works those out.

## 2. Let your agent find or create the functions

**What your agent does:** it first checks what already exists (`list_semantic_functions`). For anything missing, it asks Jedify a question, confirms the numbers look right, and saves it as a function — exposing the filters you asked for.

**What you review:** when it shows you a result, sanity-check it. A good prompt here:

```text
Before you save it, call the completion-by-department function for R&D
and show me the numbers so I can confirm they look right.
```

Your agent ends up with functions like:

| Function | Filters (parameters) |
| --- | --- |
| `_COMPLETION_RATE` | department, office, date range |
| `_COMPLETION_BY_DEPARTMENT` | office, date range |

Two things to notice. There's a **separate function per breakdown** — the "by department" chart is its own function (ask for "by office" too and you'd get a third). And `_COMPLETION_BY_DEPARTMENT` has **no department filter** — you don't filter by the field you're already breaking down by.

## 3. Let your agent build the app

**What your agent does:** generates the dashboard — UI, charts, and the data calls — wiring your filter controls to the function parameters through the Jedify SDK. You don't write this; here's the *kind* of code it produces, so you know what to expect:

```typescript
import { Jedify } from '@jedify/sdk';

const jedify = new Jedify({ apiKey: process.env.JEDIFY_API_KEY, baseUrl: process.env.JEDIFY_BASE_URL });

// filters from the dashboard's controls
const data = await jedify.call('_COMPLETION_BY_DEPARTMENT', {
  office: filters.office,          // optional — leave out for "all offices"
  start_date: filters.startDate,   // date range is required
  end_date: filters.endDate,
});
// render data using the exact field names the function returns
```

Optional filters (like `office`) can be left out to mean "all"; the date range must always be supplied.

<Note>
**Two places, two purposes.** The MCP connection you set up in your platform (server URL + API key) lets your agent *build*. The finished app needs its **own** credentials to *run* — `JEDIFY_API_KEY` and `JEDIFY_BASE_URL` (`https://api.jedify.com`) stored as your platform's app secrets. Skip this and the published dashboard loads blank. See [Authentication](/mcp/authentication#how-your-live-app-stays-connected).
</Note>

## 4. Review and adjust

Steer the result like you would a designer:

```text
Make the office filter optional so the default shows all offices.
Add a second chart: completion by office.
Show the completion rate as a percentage.
```

Good things to check:
- **Filters actually filter** — change a filter, confirm the numbers change.
- **"All" works** — clearing an optional filter shows everything.
- **Field names match** — the app reads the exact column names each function returns.

## 5. Before it ships

Ask your agent to confirm it ran its own checks:

```text
Did you run the verification check? Confirm functions are reused where possible,
the runtime uses only the SDK, and there's loading and error handling.
```

Your agent self-checks with `process_verification` before reporting done. Once that passes, the dashboard runs on its own — each function call returns quickly, with no AI in the loop.

## Steering tips

- **Reuse first** — tell your agent to check existing functions before creating new ones.
- **One breakdown per chart** — each "by X" view is its own function; just ask for each.
- **Say which filters are optional** — so your "All" options work.
- **Always confirm a live call** — have your agent run a function with real filter values and show you the rows before trusting it.
