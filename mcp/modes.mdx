Jedify's MCP server exposes three modes. The connection and authentication are identical — the mode only changes which tools your client sees.

- **Asker** _(default)_ — ask questions in plain language; get data back.
- **Editor** — have your agent make validated changes to your semantic layer, verify them, and publish only when you confirm.
- **Builder** — have your agent build data apps and dashboards using Jedify's semantic functions.

## Choose your mode

|                           | Asker mode                             | Editor mode                                                                    | Builder mode                                |
| ------------------------- | -------------------------------------- | ------------------------------------------------------------------------------ | ------------------------------------------- |
| **Best for**              | Ad-hoc questions and analysis          | Evolving the semantic layer itself                                             | Building dashboards and data apps           |
| **How you use it**        | You ask, in conversation               | You describe a change; your agent drafts it, you verify it, you confirm publish | You describe; your agent builds             |
| **Speed**                 | A few seconds — generated per question | Edits are validated instantly; publishing waits for your go-ahead              | Instant — prebuilt, no AI at runtime        |
| **Tools your agent gets** | Questioning and analysis               | The above, plus editing, versioning, and test sets                             | The above, plus function management and SDK |

## Asker mode

Ask a question in plain language. Jedify interprets it against your semantic layer, runs the query, and returns the data. Best for ad-hoc exploration, investigations, and reporting.

## Editor mode

Describe a change to your semantic layer — a new metric, a relationship, a dimension — and your agent turns it into a validated pending change. You can ask questions against the pending change, run a test set on it, and review what differs before you tell your agent to publish. Nothing goes live until you confirm — and on accounts without [Model Versioning](/semantic-fusion/versioning/overview), a Data Expert also approves the edit in Jedify first.

## Switching modes

Asker is the default mode. Where you select another one depends on how you connect:

|                                                          | Editor                                    | Builder                                    |
| -------------------------------------------------------- | ----------------------------------------- | ------------------------------------------ |
| **Claude connector**                                     | Not available — use a local client        | Not available — use a local client         |
| **Local client** — `REMOTE_MCP_URL` in the `env` block   | `https://be.jedify.com/mcp/message?mode=editor` | `https://be.jedify.com/mcp/message?mode=builder` |
| **Hosted agent or other MCP client** — server URL        | `https://be.jedify.com/mcp?mode=editor`   | `https://be.jedify.com/mcp?mode=builder`   |

The `?mode=` parameter takes precedence over every other setting, so it works the same with the browser sign-in and with an API key (a key created in the app carries Asker mode on its own). See [Connect](/mcp/connect) for the full setup in each client.
